# Development journal: Ruby Trail

The existing workspace already had a Ruby runner, shared editor, code model and value explorer. Ruby Trail reuses these components so learners can move from an explanation to an experiment without leaving the lesson.

A useful lesson from the existing extension was that printed output and return values must be explained separately. The opening lesson calls out that `p` prints a representation and returns its argument. Another was that a visual preview is useful only when its assumptions are clear: the explorer deliberately limits the transformations it predicts.

The first release of this path contains introductory examples, self-reported milestones and a guided reference tour. It does not yet contain an independently graded mastery assessment, advanced topics, or complete coverage of the official reference. Those are further work, not claims about what a learner has mastered.
